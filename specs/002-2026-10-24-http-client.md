# Specification: Development HTTP Client

- **Specification ID**: 002
- **Date**: 2026-10-24
- **Status**: Implemented
- **Owner**: Admin HTTP transport
- **Related Specification**: [Backend HTTP bootstrap](../../backend/specs/001-2026-10-24-http-bootstrap.md)

## Context & Problem

The admin has an empty layout and no backend transport. The user requests a reusable HTTP client carrying a hardcoded development token.

## Solution & User Story

As an admin developer, I can send JSON requests to the backend with the fixed Bearer token and handle HTTP errors and cancellation without duplicating transport logic.

## Architecture & Implementation Decisions

Use native fetch with a same-origin /api base, JSON request/response support, caller cancellation and a ten-second request deadline. HTTP errors carry the status code, not raw backend response bodies. No automatic retries. A separate ping function exposes the backend connectivity endpoint. No component calls it automatically and no page content is added. The Vite development server proxies /api to 127.0.0.1:8081. Production hosting must route /api to the backend; this scaffold's hardcoded token is only for local development.

## Verification Decisions

TypeScript compilation was run for the initial client. The user clarified that the restriction applies to mobile UI testing, not code tests.

## Acceptance Criteria

- Requests carry the agreed Authorization header.
- HTTP failures reject with a typed status error.
- Requests support cancellation and a finite deadline.
- The ping function matches the backend endpoint.
- Existing pages remain empty.

## Out of Scope

Login, token refresh, persistence, application queries, UI changes and production authentication.
